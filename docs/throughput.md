# Phase 2 follow-up: what the anomaly fixes cost under concurrent load

Phase 1 found two configurations that removed the client-visible anomalies:
each engine's **deterministic mode** (vLLM `VLLM_BATCH_INVARIANT=1`, SGLang
`--enable-deterministic-inference`) and, on vLLM, **disabling automatic prefix
caching** (`--no-enable-prefix-caching`). Phase 1 issued requests one at a time
and did not measure what either costs. This follow-up measures both under
concurrent load, and checks whether they still make temperature-0 output unique
when requests are batched together.

**Result in one paragraph.** Both deterministic modes cost about half the
throughput (0.46-0.57x) and roughly double the time per output token, and both
kept every prompt's temperature-0 output identical across about 37 requests per
prompt at up to 32 requests in flight. Disabling prefix caching cost no
throughput on this workload but **did not survive batching**: under concurrent
load vLLM gave 4-10 different outputs per prompt with it off, as many as with it
on. So of Phase 1's two fixes, only the deterministic modes hold under load.

## Setup

One g5.xlarge (NVIDIA A10G, `ip-172-31-6-222`), Llama 3.1 8B Instruct, vLLM
0.31.0 and SGLang 0.5.21 (container image `b1259f3ea327`, as in Phases 1 and 3),
`--max-model-len 4096`, commit `b164136`.
[`harness/run_throughput.py`](../harness/run_throughput.py) starts the server,
sends 4 unrecorded warm-up requests, then for each concurrency C in 1, 4, 16, 32
sends max(12, 4C) requests with C in flight. Requests cycle through the six
prompts in [`harness/prompts.json`](../harness/prompts.json), temperature 0,
seed 1234, `ignore_eos`, so every request generates exactly 256 tokens (all
2,200 did). Each configuration ran twice, interleaved (A B C A B C), on one
evening; the two repetitions agree within 1 tok/s at every level. Numbers are
generated by [`analysis/throughput.py`](../analysis/throughput.py); the full
table is [`experiments/throughput_summary.md`](../experiments/throughput_summary.md).

## Throughput and latency

Output tokens per second over each level's wall time (first repetition; the
second is within 1 tok/s), relative to the engine's default:

| Engine, configuration | C=1 | C=4 | C=16 | C=32 |
|---|---|---|---|---|
| vLLM default | 30 | 115 | 434 | 856 |
| vLLM batch-invariant | 14 (0.47x) | 58 (0.51x) | 237 (0.54x) | 487 (0.57x) |
| vLLM prefix caching off | 30 (1.00x) | 115 (1.00x) | 433 (1.00x) | 845 (0.99x) |
| SGLang default | 30 | 115 | 436 | 862 |
| SGLang deterministic | 14 (0.46x) | 57 (0.49x) | 233 (0.53x) | 477 (0.55x) |

* **Time per output token** roughly doubled in the deterministic modes: 65-70 ms
  (vLLM) and 67-71 ms (SGLang), against 33-37 ms by default. The relative cost
  shrinks slightly with load.
* **Time to first token** rose too: vLLM batch-invariant 74-205 ms against
  41-112 ms; SGLang deterministic 136-148 ms against 70-95 ms.
* **Prefix caching off** cost no throughput, but time to first token at C=32
  rose from 112 ms to 191-221 ms. The prompts here are about 20 tokens, so there
  is almost nothing to cache; workloads with long shared prefixes (system
  prompts), which is what the cache is for, would pay more. That was not tested.
* Both engines' defaults are within 1% of each other at every level; on this GPU
  both are limited by memory bandwidth in decode. The SGLang servers' logs were
  checked to come from SGLang.

## Determinism under batching

Distinct temperature-0 outputs per prompt across a whole run (about 37 requests
per prompt, all concurrency levels), range over the six prompts:

| Configuration | Repetition 1 | Repetition 2 |
|---|---|---|
| vLLM default | 5-8 | 5-9 |
| vLLM prefix caching off | 4-10 | 4-9 |
| vLLM batch-invariant | **1** | **1** |
| SGLang default | 3-6 | 3-6 |
| SGLang deterministic | **1** | **1** |

Phase 1, with one request at a time, saw at most two distinct outputs per prompt
in the default modes, and disabling vLLM's prefix cache made them identical.
Under concurrent load the default modes vary far more, consistent with output
depending on batch composition [He et al.], and disabling the prefix cache no
longer helps. The deterministic modes gave one output per prompt in every run.

## Consequences for the earlier phases

* The paper's statement that turning off vLLM's prefix cache removed the
  contradictions holds for sequential requests only; under load it does not.
  The recommendation becomes: a deterministic mode plus recompute (or the
  Phase 3 gateway), at about half the throughput.
* The deterministic-mode results of Phases 1 and 3 (exact recovery at
  temperature 0) were measured one request at a time; this run shows the
  property they rely on, one output per prompt, holds at up to 32 concurrent
  requests. Recovery itself was not injected under load.

## Not tested

Temperature above 0; concurrency above 32 or mixed prompt lengths; long shared
prefixes; other models and GPUs; fault injection under concurrent load.
